# Claude 专属网络配置与环境检测

围绕 Claude 网页、桌面/手机客户端和 Claude Code 的访问、环境检测与订阅页面连通性，结合已验证的网络排查经验。两套主要方案是自建 VPS 和机场＋静态 IP。执行时：先识别当前链路，准备可恢复的候选配置，验证后再切换。用户已经指定 VPS、机场或静态出口时沿用其方案，技术细节由 Agent 判断，不反复让用户选择端口、DNS、代理组等常规参数。需要的缺失信息先从当前配置和已授权连接中查找。

## 范围与不变量

- 本 skill 的主目标始终是 Claude 网络与环境。Codex、Google Play、Apple、PayPal 仅在同一网络改动涉及它们，或排查 Claude 订阅链路时作为关联项；独立的 Codex 或其它应用任务不由本 skill 承接。

- 先绑定目标设备、客户端、正在生效的订阅和用户要求的流量范围。远程任务不修改控制端网络；手机任务不能用电脑结果代替验收。
- “静态 IP”在此通常指固定代理出口，不是把 Wi-Fi DHCP 改成手动 IP。入口地址也未必等于目标网站看到的出口。
- “检查/测速/写 skill”只读；“先配置，等我切换”只准备候选，不切换；“优化”允许在指定范围内备份、修改和验证，不授权更换付费资源或清理账号。
- 保护当前可用网络、SSH、Tailscale、局域网与正在进行的任务。先验证候选再停旧方案；不为了测试同时启动两个接管默认路由的 VPN。远程修改必须有独立恢复路径。
- 保留明确的中文偏好。时区、界面语言、商店地区、付款资料是不同设置；只改用户授权部分。网络配置不需要轮换设备 ID、伪造指纹、清除 Cookie 或重置账号。
- 不把旧 IP、代理密码、订阅 URL、SSH 身份、配置 UID、测速成绩当作当前值。凭据保存到权限受限文件，不进入 skill、命令输出、截图或公开报告。
- 不以检测“全绿”为代价伪造结果、禁用检测或仅给检测域名特殊放行。检测分数不能保证账号可用、不弹 KYC、不封号或支付成功。

## 执行顺序

1. **盘点与基线**：记录目标设备、客户端/核心版本、活动订阅、系统代理、应用代理、TUN/VPN、DNS/IPv6、模式、实际组选择、规则和链路。画一行真实路径：Claude 网页/应用/Claude Code → 接管层 → 上游 → 最终出口 → 目标。
2. **按任务选参考**：
   - 新建/维护独立服务器：[VPS 方案](references/vps.md)。
   - 更换静态地址、机场中转、移除旧静态出口：[机场＋静态出口](references/static-chain.md)。
   - 测速、泄露、检测页、环境一致性：[检测与验收](references/verification.md)。
   - Claude 页面/订阅表单加载失败，以及同网配置造成的关联应用回归：[Claude 及关联应用排障](references/app-troubleshooting.md)。
   - 手机导入、USB、远程配置、时区复原：[设备适配](references/devices.md)。
3. **准备变更**：备份源配置、增强脚本、当前选择和受影响系统设置；注明恢复方法。优先订阅专属持久化覆盖，保留原有逻辑。候选核心只监听回环地址且不启用 TUN/系统代理，避免抢走现有网络。
4. **验证再应用**：按当前版本检查配置语法、组引用、规则顺序与依赖环路；候选完整代理链可用后只切换授权范围。先确认新路径可用，再处理旧连接与旧配置。
5. **读回与验收**：核对磁盘持久化、核心运行态、真实请求命中和最终出口四层。导入成功不等于正在使用；订阅显示新名字不等于选中了新节点。
6. **收尾**：删除本次临时测试规则/本地桥接与测试进程，恢复临时修改。保留已证明有效的变更，避免无收益调参。交付结果、剩余问题和回滚路径。

## 变更停止条件

候选无法解析、管理连接受威胁、关键服务回归或没有重复收益时，停止扩大改动并恢复本次变更。看到身份验证、付款拒绝或账号限制时，先区分网络层与业务层，不靠反复切 IP 和提交付款验证网络。只有实质缺失的授权、系统身份验证、付费或不可逆动作需要用户参与；其余在已授权范围继续完成。

## 交付最小格式

- 当前链路与生效范围；改了什么、保留了什么。
- 证据：出口；DNS/WebRTC/IPv6；延迟与成功率；Claude 实际访问或用户授权测试的业务是否恢复。
- 配置/备份路径；临时规则是否清理；持久化是否验证。
- **已通过 / 失败 / 未测 / 有线索但未证实**分别写清。HTTP 探测通过不能写成 Claude 聊天、Claude Code 或订阅成功；配置了回退不能写成故障演练通过。

需要重复短请求对照时，使用 `scripts/probe_routes.py --help`。它不改系统设置，只通过已存在的本地监听端口测量 HTTP，不测浏览器 DNS、WebRTC、模型生成或真正的绕过 TUN 直连。

容易误判的历史经验见 [经验与证据边界](references/session-lessons.md)，遇到相似症状时按需读取。
