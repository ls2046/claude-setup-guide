# Claude 开通与使用全流程

帮助用户从准备环境到正常使用 Claude，并处理后续订阅与账号问题。用户要求操作时，先查现状，完成授权范围内的配置、表单准备和验证，不只提供教程。技术选择由 Agent 判断，只有无法从当前设备、页面、已有配置获得的关键资料才询问。

## 从当前阶段开始

先读 [流程判断与常见问题](references/workflow.md)，确定目标设备、账号、购买渠道和当前卡点。用户只查退款就查该订单，不重配网络；只配置手机就操作该手机；只问原因就解释证据，不自动购买或取消服务。

一般开通顺序：网络准备 → 电脑/手机检测 → 邮箱与注册 → 订阅支付 → 若出现 KYC 则完成验证 → 核对权益与使用。KYC 也可能在其他阶段出现，按实际页面分支处理。退款与解封是异常处理，不是每位用户必须走的步骤。

## 操作方式

1. **识别事实**：读取当前页面、设备和实际配置，区分网络、认证、订单、权益及风控问题。账号只保留必要信息，报告中脱敏。
2. **准备后执行**：修网络先备份并测试候选；处理订单先核对账号、日期、币种、金额、订单及现有申请。把拟提交内容准备到可核对状态，再处理必要的确认。
3. **完成可做的部分**：按当前工具能力直接操作。已有授权不重复询问；不要把普通配置交回用户。确实需要用户验证或工具规则要求接管时，指出具体页面、动作及原因，不笼统说“请自行处理”。工具受限时保留现场并给最短替代步骤。
4. **接着完成**：用户说“已登录/已授权/已提交”后，读回现状并继续后续核对，不重复上一轮步骤。表单提交状态不明时先查现有订单/工单，避免重复扣款或重复申请。
5. **验证结果**：配置写入、活动配置、真实请求和出口分层核对；订单成功、Pro 权益、实际聊天分层核对；申请提交、审核通过、款项到账分层核对。

## 保留的边界与判断

- “检查/测速”默认只读；“先配好等我切换”不提前接管网络。写或更新 skill 不等于授权操作真实账号或设备。
- 保护唯一可用网络、SSH/Tailscale 和当前 Codex 连接。远程任务不改控制端网络。候选验证后再切换，失败恢复本次变更；不同时启动互相抢路由的 VPN。
- 静态 IP 指固定代理出口，不是 Wi-Fi 手动地址；入口不一定是出口。代理协议和端口以实际支持为准。
- 手机、电脑分别验收。代理地区、系统语言/时区、商店国家、账单资料、订阅币种分开处理，不捆绑更改。保留用户偏好的语言。
- 普通技术参数由 Agent 决定；付费资源、不可逆改动、敏感授权及最终交易遵守当前工具规则和具体用户授权。不得换工具绕过要求的确认或用户接管。
- 密码、验证码、Cookie、代理认证、卡号及身份证件不进入仓库、报告或聊天输出。用户在官方页面完成敏感输入；证件和活体核验由本人完成。
- 不承诺免 KYC、稳定不封号或退款成功。没有本人可用证件时查官方支持的其他验证或支持渠道，不提供借用身份、伪造证件、购买已验证账号或规避限制的方法。
- 价格、地区限制、验证材料、退款时限、界面入口是易变信息：回答前看当前官方页面和真实账号状态。教程中的个人经历用于选排查方向，不升级为普遍政策；不要反复添加与当前问题无关的免责声明。

## 收尾与输出

先给结论和已完成动作，再给关键证据与剩余步骤。区分已通过、失败、未测和未证实线索。需要等待平台审核时记录提交时间、订单尾号、状态及下次查询入口，不把等待写成完成，也不擅自创建定时任务。

网络变更注明备份、回滚和持久化情况，清理本次临时测试规则与桥接。取消续费后读回到期/续费状态；提交退款后保留回执并验证该笔订单。

短请求对照可用 `scripts/probe_routes.py --help`，只通过已有本地代理测试 HTTP，不代替浏览器泄露、模型生成或交易验证。经验边界见 [经验记录](references/session-lessons.md)。
