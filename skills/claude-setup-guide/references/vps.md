# 自建 VPS

目标是独立 VPS 落地的可维护代理，不把“VPS 一定更稳定”当作结论。若使用机场中转 VPS，那是另一条链路，应单独对照，不能混称独立 VPS。

## 部署与恢复

- 核对当前 SSH 别名解析、目标身份、系统/架构、已有代理、负载、端口和防火墙。没有明确重装授权不重装，不覆盖其它服务器的 SSH 别名。
- 复用可用部署；新建时按需求选当前兼容协议。VLESS/Reality 可作为 TCP 候选，Hysteria2 可作为 UDP 候选，不把协议迁移当作每次排障的前提。
- 从官方发布源取得固定版本，检查发布摘要、服务端及客户端语法，不直接执行不明一键脚本。配置、密钥与认证信息限制权限，不暴露管理 API 到公网。
- 独立服务、配置和最小防火墙规则；先确保实际 SSH 端口仍通。新增密钥先在第二个连接验证，再考虑已授权的 SSH 加固。远程接管网络前准备救援入口或可取消的自动回滚。
- TLS 使用可验证证书，不能以关闭证书校验修复握手。Reality 的密钥/目标兼容性和 HTTPS 订阅分发证书分开处理。可本地导入就不默认新增面板、公开订阅服务或证书系统。
- 检查服务启动、端口、日志与客户端实际出口。端口 open 不是代理成功。每个设备凭据和导入结果单独管理。

## 提速只做有证据的变更

先比较 VPS 自身出站和用户到 VPS 的完整代理传输，检查资源、带宽额度、重传和目标限制。ICMP 丢包不直接等于实际 TCP 丢包，`bytes_retrans/bytes_sent` 不是端到端丢包率。

需要验证 Hysteria2 时保留原 TCP 节点，增加独立 UDP 端口/服务，优先使用默认自适应设置。带宽参数不得按网卡标称速率夸大；固定速率高于线路承载可能恶化拥塞。UDP 受限、无重复收益或引入回归时停止试验并回原节点。

MTU、TUN 栈、并发、拥塞控制每次只改一项，以原→候选→原对照验证。不要一键改内核所有参数。核心健康检查间隔不是故障恢复时限；同机双协议回退不能应对 VPS 本身宕机。

## 验收和交付

记录服务/核心版本、实际端口、配置备份、客户端增强位置、出口和稳定性结果；若配置了证书续期/服务重启钩子，区分“已配置”和“真实续期已完成”。停旧 VPS 或退款可能永久丢失数据、让代理失效，不能借网络优化自动执行。
