# 订阅、商店与权益

## 先核对购买上下文

从当前页面确认 Claude 账号、商店账号、购买渠道（网页/Apple/Google Play）、套餐周期、含税金额、币种、已有订阅和付款状态。先找现有订单，避免把“未交付权益”当成“没买过”。

教程偏好 Google Play 加本人国内发行、支持外币支付的银行卡，并记录招商万事达普卡的使用经验；这是经验选项，不保证所有地区或银行卡都支持。不代申请金融账户、不固定推荐某张卡，也不把 Apple 礼品卡那次失败说成该渠道普遍不可用。

## 付款方式与商店地区

- Google Play：检查当前账号的付款和订阅页面。按真实账单资料添加用户指定方式；卡号、安全码、银行验证由用户在官方界面完成。核对付款弹窗实际选中的账号和方式。
- Apple：检查“媒体与购买项目”账户及付款设置，不能用 iCloud 登录账号代替判断。礼品卡适用地区和购买账户地区要匹配；余额充值与 Claude 订阅订单是两笔不同交易。
- PayPal：网页能打开与 Apple 扣款授权成功是两件事。确认官方支持的付款地区、本人账号和真实资料；登录成功后仍拒绝时保留错误及授权状态，不反复换 IP 重试。
- 商店地区、Google Payments/Apple 付款资料、系统地区、IP 国家、应用语言和既有订阅币种分别核对。已有 CA$ 订阅不会因切美国 IP 自动变 USD。
- 仅在用户明确要求且符合平台迁移条件时处理国家/地区变更。先检查余额、有效订阅、家庭群组和迁移限制，准备真实资料；不要虚构地址、自动关闭付款资料或删除家庭组。
- 搜不到 Claude：先查官方应用入口、当前账号和兼容性。第三方同名应用、安装包或容器不等于官方可订阅环境。

## 支付失败与扣款未开通

| 证据 | 处理 |
| --- | --- |
| 表单空白、资源超时 | 使用应用排障参考定位失败请求，必要时最小范围路由对照；不发起扣款试网 |
| 401/登录过期 | 恢复当前官方会话，回到原流程，不重复创建支付资料 |
| 拒付/地区错误/银行验证失败 | 记录完整错误类别，检查商店与银行支持条件，避免不停提交相同付款 |
| 银行预授权、订单 Pending | 查订单最终状态及账单，不把暂扣当成已入账，也不重复购买 |
| 成功订单但 Claude Free | 核对原购买 Claude 账号、应用版本、当前套餐，使用实际存在的恢复购买入口；失败转支持/退款 |
| 网页提示已有 App Store 订阅 | 回原渠道查有效期、取消/退款状态及绑定账号；取消续费不等于即时到期，别再建新号绕过 |
| 付款后 KYC | 标记“已扣款，等待身份验证”，进入 KYC 流程；验证后再核对权益 |
| 显示 Pro 但聊天失败 | 查限额、服务状态、模型可用性和真实请求，不再次收费升级测试 |

关键状态不明时先读回原订单。重试仅在明确纠正失败原因后进行；仍失败则准备证据交官方支持。不要清除账号数据或假写 Pro 环境变量来解决权益。

## 切换渠道与取消续费

用户要改用网页或另一商店时，先查旧订阅的到期和退款结果，再按当前官方规则处理；不保证取消后立即可跨渠道购买。用户已明确“还在续费就取消”时执行该笔订阅取消，验证续费日期变成到期状态；无订阅、已取消、待退款分别记录。

## 当前规则的查询入口

- [Claude 账单说明](https://support.claude.com/en/articles/8325618-paid-plan-billing-faqs)：网页和商店购买的管理入口不同。
- [Google Play 付款方式](https://support.google.com/googleplay/answer/4646404)
- [Google Play 国家/地区](https://support.google.com/googleplay/answer/7431675)：核对居住地、付款方式、家庭组和等待限制；不固定历史等待天数。
- [Apple 支持](https://support.apple.com/)：查对应地区可用付款方式与取消订阅入口。

具体交易前先完成可核对的套餐、金额、账号和续费信息，再按当前工具规则完成确认或用户接管。申诉与退款见 [退款参考](refunds.md)。
