# 流程判断与常见问题

先读取可见现状，只补充阻塞当前动作的信息，不把下表变成用户必须填写的问卷。

## 定位任务

记录设备与客户端、当前 Claude 账号、商店账号（如涉及）、购买渠道、报错原文、是否已扣款/提交、用户最终想要的结果。Claude 账号和 Apple/Google 账号可能不是同一个邮箱，不因不同就认定错误；要与购买时的绑定关系核对。

| 用户说法 | 优先检查 | 下一步 |
| --- | --- | --- |
| 网络慢、一直转圈、检测分数高却很慢 | 请求阶段、长尾、丢失样本、真实规则与完整链路 | 先对照路径，区分风险评分与带宽，不先改时区 |
| 想开通，不懂选什么 | 现有机场/VPS、预算偏好、设备 | 经济方案可复用机场加固定出口；有独立 VPS 则沿用，先准备候选 |
| 手机上显示国内 IP | 哪张检测卡片、对应请求路由、VPN 覆盖 | 按分流目标核对，不仅给检测网站特殊放行 |
| 检测页空白 | 页面加载、浏览器/WebView 版本、JS 错误 | 换兼容浏览器或独立检测，标明未完成项 |
| 收不到验证码/登录循环 | 邮箱拼写、垃圾箱、原发起设备、请求是否成功 | 在原登录会话使用有效新邮件；保留其他登录态 |
| 搜不到 Claude/商店闪退 | 官方应用入口、设备兼容、Play 服务和认证、商店账号地区 | 走设备或商店流程，不把换 IP 当作万能修复 |
| 地区已是美国，仍显示 CA$ / 日文 | 商店付款资料、既有订阅、应用语言和翻译 | 分别解释币种与语言；不重复购买验证 |
| 支付表单加载失败 | 资源、iframe、支付接口、认证状态 | 先网络/页面排障，表单完整后再进入付款 |
| 已扣款还是 Free / 已有 App Store 订阅 | 原渠道订单状态、Claude 绑定账号、恢复购买入口 | 查权益与原订阅，避免跨渠道重复付款 |
| 弹 KYC | 提示类型、官方入口、已提交状态 | 本人验证；失败查错误并准备官方支持材料 |
| 账号封了 | 停用通知、是否还能进入申诉页、有效订阅 | 解封与退款分开，按用户目标行动 |
| 查退款进度 | 原付款账号、原订单/工单、最新状态 | 只查进度，不重新申请、不假定批准 |
| 还在续费就取消 | 当前订阅与下次续费状态 | 已授权则取消并读回；已取消则停止，无需退款重提 |

## 阶段验收

- 网络：目标设备实测出口正确，必要请求成功；分数与速度各自报告。
- 注册：进入正确账号，所需验证完成；注册成功不代表已付费。
- 订阅：成功订单及对应权益可见。若停在 KYC，交付“已扣款，待验证”，不要写开通全部完成。
- 正常使用：核对套餐和用户授权的简单聊天；Claude Code 还需独立确认进程认证和链路。
- 退款/取消：金额状态、续费状态分别读回。平台受理不等于资金到账。

当前流程走通后停止扩大修改。必须等待用户/平台时明确已完成什么、下一步需要什么；能独立完成的证据整理、问题解释和模板准备先完成。
