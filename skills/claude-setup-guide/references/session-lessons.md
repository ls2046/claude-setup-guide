# 经验与证据边界

这里提炼的是排查经验，不包含私有日志、设备地址或凭据，也不代表读者当前设备的状态。

## 可复用的判断

- 同一静态出口换中转后可能改善吞吐，但某次胜出的中转在另一天也可能超时。保存可重复的测试方法，不固定某个节点永远最快。
- 同一供应商的 HTTP 和 SOCKS5 候选可能表现不同，应在同一上游、同一目标下交替测试，不能从单次失败推出某个协议普遍不可用。
- Claude 固定出口与关联应用的性能需求可以不同。只有获得相应授权并验证目标规则后，才对明确的应用或域名做小范围分流。
- 长会话和大量图片可能是应用故障的排查线索；未捕获真实请求和关闭码前，不把它们写成重连故障的根因。
- 手机导入成功、代理 App 运行中，不代表检测已完成。浏览器兼容性问题和 GeoIP 数据库差异应单独记录。

## 用户要求对应的执行方式

- 原网络仍然可用：先测试候选，保留旧方案和恢复路径。
- 不允许更新订阅：使用已有订阅快照与本地增强，不刷新远程订阅。
- 其他配置不要动：只改授权的域名或进程，临时规则用完恢复。
- 反馈应用回复慢：区分请求、持续流和模型生成，不拿下载峰值代替。
- 速度已经满足需要：优先成功率、长尾和稳定性，不为跑分增加复杂度。
- 手机也要配置：在目标设备读回并实测，不以电脑结果代替。
- 重启后失效：检查端口、进程环境、加载顺序及持久化覆盖。
- 检测通过再使用：如实报告结果；检测分数衡量站点定义的风险信号，与网络带宽、账号验证结果分开。

注册、订阅、身份验证与退款现在由专门参考文件处理，不把它们混作网络故障。教程里的个人样本用于定位问题，不作为免验证、普遍拒付或退款成功率的依据。
