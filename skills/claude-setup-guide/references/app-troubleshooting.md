# Claude 访问、订阅页面与关联应用故障

## Claude 主流程

先明确故障发生在 Claude 网页、客户端还是 Claude Code，以及登录、静态资源、会话连接或订阅支付哪个阶段。检查该目标实际生效的代理来源、核心规则和完整链路，再与已验证候选做对照。浏览器可达不能代替 Claude Code 进程连通；网页资源成功不能代替登录、聊天或订阅权益成功。请求错误需区分网络失败与认证/业务返回，不把账号限制当成网络故障。

以下 Codex 经验仅用于保护同一设备现有工作连接、检查 Claude 网络变更的副作用。没有关联问题时跳过，不扩展 Claude 任务范围。

## 关联项：Codex 慢、重启后断网、重连 5/5

“5/5”是重试耗尽的表现，不是故障分类。先记录版本、发生时间、影响所有会话还是某一个、错误/关闭码与请求阶段。用户明确要求联网搜索时必须搜索，优先当前 OpenAI 文档和官方仓库问题，注意版本与发布时间；GitHub 个案是线索，不当作已证实根因。

1. **代理来源**：检查当前本地监听及归属进程、系统代理、启动环境、`HTTP_PROXY/HTTPS_PROXY/ALL_PROXY/NO_PROXY`、应用配置和存在时的 `~/.codex/.env`。不假定所有版本都会读取某文件；从当前进程/日志核实。历史端口失效是检查项，不是让新机器固定用 7897 的理由。
2. **接管冲突**：看应用和后台进程实际去向、TUN 与显式代理是否重复、机场客户端与 Clash 是否抢路由。先证明 Clash 单独能承担连接，再在授权范围切换，不先关掉唯一可用线路。
3. **真实请求**：检查实际失败的域名、命中规则、上游、TLS、长连接/流式响应。不要因 Google 打开、HTTP 401/403 或普通 GET 成功就宣布 Codex 恢复。
4. **选路**：比较机场单跳、静态链、VPS 的短请求和真实持续会话。若 Codex 不要求静态 IP，且用户授权优化，可只给已确认的 Codex 进程及服务域名选稳定路径，保持 Claude 和其它网站原出口。核对进程识别是否实际有效；不在共享 CDN 上按整个 IP 段大范围改路由。
5. **非网络原因**：仅老会话失败而新任务正常时，检查上下文大小、图片数量、客户端错误和服务状态。不得写死某个消息体阈值、复制过时 WebSocket 开关或随意替换 provider/base_url。创建新会话须用户明确要求；保留原记录，不删除历史，精简交接不携带全部内嵌图像。
6. **应用重启**：需要读取新环境时先保护未发送内容和任务，按现有授权正常重启目标应用，读回环境/路由并以实际回复验证。诊断进行中的自身 Codex 不能无回执地关闭导致失联。

区分网络首响应、模型首 token、模型思考、长上下文/工具运行时间。不得把降低推理档位当作偷偷改善网络的手段。

来源：[Codex 官方配置参考](https://developers.openai.com/codex/config-reference)、[官方问题检索](https://github.com/openai/codex/issues)。先检查本地版本/配置，必要时再核对当前官方说明。

## 支付表单或登录组件加载失败

先查看真实浏览器 Network/Console：主页面、JS、iframe、支付会话接口、登录授权页、验证码资源分别有什么状态。记录脱敏后的域名、方法、状态、耗时、错误与核心路由；不抓取或传播卡号、Cookie、验证码、完整带令牌 URL。

- 请求超时/TLS失败/连接重置：相同目标分别对照原链路和候选，确认是 DNS、上游、落地或规则问题，再做小范围调整。
- 静态资源缓存/扩展拦截：有明确证据才处理指定站点缓存或指定扩展，不清空浏览器、登录态和全部配置。
- 401：通常需要有效认证，先看会话是否过期；403/风控/地区/付款拒绝：读取具体返回，不承诺代理能修复。
- Cloudflare Error 1005 且说明 ASN 被禁：属于网站对网络来源的限制，不是页面按钮坏了；只在用户允许时测正常直连或其它合法连接。
- PayPal 页面能加载后拒绝 Apple 授权：网络恢复与业务授权分开，核对真实账号地区/付款资料/平台支持；停止反复改 IP 或支付重试，不伪造地址。

如确证需要临时让商店及下载域名走机场，只覆盖观察到的必要域名，记录变更前路由，完成下载后恢复。支付流程相关动态接口优先保持一致的稳定出口，不把拆分不同国家出口当作默认优化。不要照抄固定域名清单，也不要把整组 Apple/Google/Cloudflare 全球改路由。

验收必须回到原页面看表单完整渲染、资源完成或用户要求的业务结果。仅做诊断不授权实际购买或退款。用户明确要求处理订阅或退款时，转到 [订阅与支付](subscription-payments.md) 或 [退款与申诉](refunds.md)，完成已授权流程；付款与账户验证遵守当前工具规则。

## 商店及账号地区

Google Play/Apple 的商店国家、付款资料、账号地区、显示币种、系统地区和应用语言相互独立。切换代理国家不等于商店迁移，既有 CA$ 订阅也不会自动变 USD。地区规则与等待期按当日官方说明核对，不保证某个固定时长。仅网络任务不增建付款资料、不填虚构地址、不重复买订阅。
